# USB 再列挙ハーネスへの道 — ANE-LX2J 現状と計画 (2026-10-02 昼)

## いまの状態

- 端末はリカバリ画面で待機中（先ほどの USB プローブの自動フォールバック）。
- **音量下 + 電源を1回**押すと、待ち受けスクリプトが自動で:
  ストック復元 → Android 起動 → 画面点灯設定 → **L1 USB プローブ投入** まで進みます。
- つまり以降のサイクルは「1回押すだけ」で回ります（復旧だけは物理ボタンが要る、
  というのが現時点の制約 — 下の「ボタン不要化」参照）。

## 今日の大物成果

1. **USB プローブ敗因の特定**: DCTL（attach ビット）だけを叩いてもホストは沈黙
   （2回目も kern.log イベント 0）。理由は **LK が USB のクロックとリセットを
   畳んでからカーネルにジャンプしている**こと。
2. **ベンダー一次ソースから完全な起動手順を抽出** — `dwc_otg_hi6250.c` の
   `init_usb_otg_phy_hi6250()`:
   CRG+0x40 の3ゲート → PCTRL+0x64（abb）→ CRG+0x94 の
   リセット解除4種 → AHBIF ctrl0/ctrl3（eye pattern）→
   PHY POR → PHY → OTG の解除 → AHBIF ctrl2 → DCTL attach。
   → `ane_usb_l1_probe.S` として実装、**QEMU 検証 PASS**
   （この検証が `movk` のビット組み立てミスを1つ検出した）。
3. **L1 プローブは halt 版** = attach が出れば安定してホストに見え続ける
   （hung ブートは ~6-7 分で LK の自動フォールバックに入る既知挙動）。

## 判明した重要な制約

- **pstore は Android のユーザー空間が起動時に消費する**。
  「ストック復元 → Android → 読み出し」は必ず空になる。
  → 読み出しは **(a) プローブ自身が実行中に読む、(b) USB 再列挙など Android を
  介さないチャネル** のどちらかで行う。**今作っているのはまさに (b)**。

## ボタン不要化（未解決・正直な状況）

再起動後に自動で fastboot へ戻す方法は2経路とも未完成:

1. **LK の内部関数を payload から呼ぶ** — 方法（VBAR から実アドレスを導出して
   `reboot bootloader` 相当を呼ぶ）は立ったが、文字列の xref 探索
   （adrp+add / 64bit ポインタ / 32bit オフセット）が全て空で、
   フラット逆アセンブル前提のアドレッシングモデルと実像が合わない。
2. **PMIC の理由レジスタを直接書く** — `HRST_REG0 = base+0x18B`、
   `BOOTLOADER = 0x01` まで判明。ただし転送が SPMI で、
   `hisi_pmic_reg_read/write` の実装はソースツリーに無い（blob）。

当面は「1ランにつき1押し」で回し、L1 が通れば少なくとも
**観測**（読み出し）は完全自動になる。

## 次にやること（復帰後、自動）

1. 画面点灯 + L1 プローブ投入（`ane_usb_l1_run.sh`）。
2. attach が出れば: `/sys/bus/usb` で列挙確認 → 次の L2（ディスクリプタ応答）。
3. 出なければ: PHY 内部レジスタ（0xfe000000）と abb PLL の調査へ。
4. Fullerene 側: 同じ手順を Rust に移植（`platform/ane.rs` + usb モジュール。
   新規トップモジュールは全 crate root で `#[path] mod` 宣言が必要な点に注意）。
