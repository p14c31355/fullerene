## Work landed tonight

1. **`build.rs`**: `cargo:rerun-if-env-changed` for `FULLERENE_ANE_ENUM_DIAG`
   and `FULLERENE_ANE_PANIC_PEEK`. Without it cargo reused the old cfg and the
   "panic-hold" artifact booted to the desktop — the "still the home screen"
   report. Verified with `strings Image | grep -c 'PEEK HOLD'` = 1.
2. **Force paint path** (`ane_fb.rs`): `paint_at_force`, `flush_row_force`,
   `paint_hex_at_force`. The enumeration ledger now lands on the panel even
   when `desktop_owned()`/`irq_quiet()` is set, which is the state a failed
   bring-up is in. Ledger repainted every 4096 wait-loop passes (256 in the
   ENUM_DIAG serve loop).
3. **Peek hold is now bounded**: paint the previous boot's dying words, hold
   ~45 s, then `panic_reset_to_bootloader()` so the device returns to LK
   without a human.
4. **Touch reaches the shell** (commit `c9d6a328`): the poll loop publishes one
   sample via `solvent::arch::aarch64::set_touch_panel`; the shared
   `poll_mouse_state()` maps panel pixels to canvas coordinates with
   `rotate::touch_to_canvas` and pushes MouseMove/MouseButton. A touch edge
   runs `desktop::tick_input()` (one shell frame + flush).
   `cargo test -q -p solvent rotate`: 8 passed.
5. **Launcher layout** (commit `16d8d38b`): one `HomeLayout` owns the grid
   geometry for render, press feedback and `hit_test`; a release on a tile
   opens the desktop.

## Next, in order

1. Flash `v331z7-homehit`, read the panel photograph:
   - `SETUPS` = 0 → the setup packet never reaches our handler (RX pop / reset
     ordering).
   - `SETUPS` > 0 but `ADDR` = 0 → the first SETUP is answered wrongly
     (`-71`: stale SETUP_BUF, or `stall_ep0` from a mis-decoded bmRequestType).
   - `ADDR` > 0, `CFG` = 0 → SET_ADDRESS/GET_DESCRIPTOR(config) path.
2. Then the touch check: press a tile (accent highlight appears), release
   (desktop paints). If the highlight appears but the coordinate is mirrored,
   the `touch_to_canvas` orientation is the only suspect.
3. USB item worth revisiting with the ledger in hand: `init()` deliberately
   does not touch the inherited TX FIFO (`ane_usb_dev.rs:2373-2378`) — the
   first EP0 IN of a cold session can carry loader leftovers. `GRSTCTL`
   `TXFFLSH` on EP0's FIFO at init is the spec-correct way to make that
   deterministic.
