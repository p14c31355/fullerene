## 再設計の 3 本柱

### 1. レイヤー分離 (usb_dev の解体)

```
platform/ane/usb/
  phy.rs        クロック/リセット/PHY (usb_bringup の 200 行)
  dwc2.rs       DWC2 コアドライバ (EP0/EP1 FIFO, RESET, SETADDR)
  fastboot.rs   fastboot プロトコル状態機械
  adb.rs        ADB プロトコル (CNXN/OPEN/deferred dispatch)
  bus.rs        EP0/EP1 の初期化 + 再アーム
recovery.rs     心拍/ゾンビ/凍結検知 (boot_recovery_check 群)
```

- dwc2.rs は pure ハードウェアドライバ (診断ゼロ、トレーニングフックのみ)
- fastboot/adb は wire プロトコルのみ (MMIO を直接触らない)
- 診断はリングイベントの macro 経由で一本化 (現在 event() 直呼びが散在)

### 2. 診断の構造化 (デバッガビリティ)

- **リングイベントマクロ**: `ring!(b"TAG", value)` — 現在の text_puts 直呼び + 手動 hex 変換を置換
- **ステージ列挙型**: STG_STAGE のバラバラな b'H'/b'R'/b'K' を enum に (Stage::Home, Stage::Reenum...)
- **T1〜T8 方式の一般化**: 全 bringup シーケンスに番号付きマーカー (停止位置が即特定できる)
- パネルはユーザー UI 専用 (v331j で確定済み)、診断はリング 100%

### 3. 列挙安定性 (次の実機ブロッカー)

- **responder arm を boot 最序盤へ**: storage probe より前に USB を上げる
  (現状: first light → storage → USB arm → host がタイムアウトする)
- LK 窓との競合を構造的に排除: LK が 列挙している間にカーネルが arm し直す
  遷移を 1 回の bus reset に正規化
- ホスト側エンジンは「列挙失敗=デバイス側遅延」として 90 秒待つ (現状維持)

## 実施順 (次セッション)

1. usb/ ディレクトリ分割 (動作変更なしの純粋移動, テスト維持)
2. ring! マクロ + Stage enum 導入
3. responder arm の前倒し (実機 A/B)
4. ane_touch の T マーカー解析結果を反映した修正版プローブ

## 制約

- x86_64 を壊さない (platform/ane 配下のみの変更に限定)
- テスト 6/6 を維持、移動中も cargo test を通し続ける
- CI は let-chains 禁止


## 追記 (ユーザー指示): 端末共通処理の集約

「端末において共通のことをやっているところはなるべくまとめる」

現状の非対称: bramble 側は既に構造化済み (usb_clock.rs / usb_reset.rs に
リソース記述子ベースの bringup、DT 由来の clock plan)。ane 側は生レジスタ
直書き。共通パターンを common/ に集約し、各 SoC は差分のみ実装する。

### common/ に集約するもの (端末共通)

| 抽象 | 現在の重複 | 集約先 |
|---|---|---|
| USB bringup 手順 | ane: mod.rs 直書き / bramble: usb_clock+reset | common/usb/bringup.rs (フロー) + 各 SoC の resource descriptor |
| リング診断 | ane_fb::event / blackbox text_puts 直呼び 48 箇所 | common/ring.rs (ring! マクロ + Stage enum) |
| フレームバッファ診断 | ane_fb 前提の実装 | common/fbconsole.rs (帯域/パレット/行ピッチ抽象) |
| タッチ | ane_touch のみ | common/touch.rs (I2cBus トレイト経由、FT/Goodix 両対応) |
| レギュレータ/クロック | common に既にあり (regulator.rs, clock.rs) | ane 側もこれを使うように寄せる |
| 復帰機構 | ane_usb_dev 内蔵 (心拍/ゾンビ/凍結) | common/recovery.rs (ウォッチドック抽象の下) |

### 目標構造 (端末追加時の差分を最小化)

```
platform/common/       ← 端末共通 (ドライバ・プロトコル・診断・復帰)
platform/ane/          ← ANE 固有: 定数表, resource descriptor, SoC クセ
platform/bramble/      ← Bramble 固有: 同上 (既に大部分構造化済み)
```

新しい端末 = 定数表 + resource descriptor の記述だけで立ち上がる状態を
目標にする。ane_usb_dev.rs の解体はこの構造への配置替えを兼ねる。
